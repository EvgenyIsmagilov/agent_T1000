# SEO: полный цикл (Google + Yandex)

Навык для сквозной работы с поисковой оптимизацией. Два принципа:

1. **Разделяй Google и Yandex.** Движки ранжируют по-разному. Техбаза общая, но
   семантику, регион, поведенческие и коммерческие факторы веди и отчитывай **раздельно**.
2. **Гибрид без фантазий.** Есть MCP/API — тяни реальные данные. Нет — работай по
   методологии и ручным проверкам, но **никогда не выдумывай** частотность, позиции
   или трафик. Нет источника → скажи, что именно подключить.

## Шаг 0. Собери вводные — до любой работы

- **Движок:** Google / Yandex / оба.
- **Рынок и регион** (для Яндекса региональность критична).
- **Язык:** русский → морфология ядра обязательна (см. ниже).
- **Тип проекта:** коммерция / контент-медиа / услуги / локальный бизнес.
- **Что доступно:** какие MCP настроены, какие ключи есть (GSC, Wordstat, Metrika…),
  есть ли доступ к сайту/CMS.
- **Цель:** трафик, позиции по ядру, индексация, конкретные страницы.

Не задано — спроси. Если ответа нет, зафиксируй допущение явно («предполагаю оба
движка, регион РФ») и двигайся.

## Чем Google и Yandex различаются (быстрый ориентир)

| Аспект | Google | Yandex |
|---|---|---|
| Поведенческие факторы | важны | вес выше; накрутка = бан |
| Региональность | умеренно | сильно (регион в Вебмастере, поддомены/папки) |
| Коммерческие факторы | косвенно (E-E-A-T) | прямая оценка (цены, доставка, отзывы) |
| Ссылки | качество доноров | осторожно (Минусинск за покупные) |
| Переспам текста | Helpful Content | Баден-Баден |
| Частотность спроса | Keyword Planner / GSC | Wordstat (операторы `"" ! + -`) |
| `robots.txt` | canonical/параметры | `Clean-param`; `Host`/`Crawl-delay` мертвы |
| Морфология ядра | не критично | обязательна |

## Универсальный процесс (каркас, движко-независимый)

Проходи по шагам; на каждом ныряй в `google.md` / `yandex.md` за деталями движка.

1. **Вводные и цели** — Шаг 0.
2. **Технический аудит** — индексируемость (`robots.txt`, `sitemap`, canonical, коды
   ответов), скорость/Core Web Vitals, mobile, архитектура и ЧПУ.
3. **Семантика** — сбор запросов → **морфология и кластеризация** (для RU) → разметка
   интента и коммерческости → распределение по посадочным.
4. **On-page** — title, description, заголовки, контент под интент, Schema.org, alt.
5. **Структура и перелинковка** — вложенность, хлебные крошки, ссылки на приоритетное.
6. **Внешние факторы** — ссылки и репутация; естественность важнее объёма (осторожно
   с фильтрами).
7. **Мониторинг** — позиции, индексация, поведение/конверсии; итерации.

## Морфология и семантическое ядро (RU)

Для русского ядра лемматизация обязательна — иначе ядро тонет в словоформах-дублях.

1. Прочитай `references/morphology.md`.
2. Проверь зависимость: `python3 -c "import pymorphy3"`. Нет — предложи
   `pip install pymorphy3` (не запускай установку без согласия пользователя).
3. Используй бандл-скрипт:
   ```bash
   python3 scripts/semcore.py dedup keys.txt > uniq.txt        # схлопнуть словоформы
   python3 scripts/semcore.py cluster uniq.txt --min-common 2  # черновые кластеры
   ```
   Лемма-кластеризация — быстрый черновик; коммерческую точность уточняй по
   пересечению выдачи (SERP). Детали — в `morphology.md`.

## Формат вывода

- Отчёт и рекомендации — **раздельными секциями «Google» и «Yandex»** (общая техбаза
  может идти отдельным блоком «Общее»).
- Приоритизируй: влияние × трудозатраты.
- Каждый пункт: **что** сделать, **почему** это влияет, **как проверить** результат.
- Явно помечай, где вывод основан на реальных данных из источника, а где — гипотеза
  без доступа к нему.

## Красные линии

- Не выдумывай метрики. Нет доступа — так и скажи.
- Не предлагай накрутку поведенческих факторов и покупку SEO-ссылок — в Яндексе это
  прямой путь под фильтр (накрутка ПФ, Минусинск), в Google — риск ручных санкций.
- Изменения на боевом сайте (правки `robots.txt`, редиректы, удаление страниц,
  массовая замена мета) — сначала опиши последствия и согласуй с пользователем.
