# SEO под Google

Читай этот файл для работы под Google (глобальный/англоязычный рынок и рунет, где
Google — второй движок). Про отличия рунета и приоритет Яндекса см. `yandex.md`.

## Инструменты и деградация

Навык гибридный: используй API/MCP, если настроены; иначе — ручные проверки. Никогда
не выдумывай цифры (позиции, частотность, трафик) — если источник недоступен, так и скажи.

| Задача | Инструмент (авто) | Fallback (руками) |
|---|---|---|
| Позиции, клики, показы, CTR, индексация | Google Search Console API (`mcp-gsc`) | GSC веб-интерфейс; оператор `site:` |
| Частотность и идеи запросов | Keyword Planner API (`google-keyword-planner-mcp`) | Keyword Planner веб; автоподсказки, «Похожие запросы», People Also Ask |
| Скорость и Core Web Vitals | PageSpeed Insights API, CrUX API | pagespeed.web.dev; Lighthouse в DevTools |
| Поведение и трафик | GA4 (Data API) | GA4 веб |
| Структурированные данные | — | Rich Results Test, Schema Markup Validator |
| Бэклинки, SERP, конкуренты | DataForSEO / Ahrefs MCP (опц.) | руками из выдачи; недоступно без платного API — так и скажи |

Проверь доступность инструмента перед тем, как обещать данные: нет ключа GSC —
не рисуй график позиций, а объясни, что подключить.

## Что ценит ранжирование Google

- **Соответствие интенту.** Тип страницы должен совпадать с намерением: коммерческий
  запрос → каталог/карточка, информационный → статья/гайд. Мисматч интента — частая
  причина непопадания в ТОП при формально хорошей оптимизации.
- **E-E-A-T** (Experience, Expertise, Authoritativeness, Trust). Особенно критично для
  YMYL-тематик (здоровье, финансы, право): авторство, экспертиза, репутация, факты,
  ссылки на источники.
- **Helpful Content** — контент для людей, а не под поисковик. Тонкий/шаблонный/
  «ради ключей» текст режется на уровне ядра ранжирования.
- **Core Web Vitals** (полевые данные CrUX): `LCP` < 2.5 c, `INP` < 200 мс,
  `CLS` < 0.1. Влияют как тай-брейкер и на поведение.
- **Mobile-first** — Google индексирует мобильную версию. Контент и разметка
  на мобиле должны быть полными.
- **Ссылочный профиль** — качество и тематичность доноров важнее количества.
- **HTTPS**, отсутствие агрессивных interstitial, стабильность.

## Технический аудит — чеклист

- **Индексация:** `robots.txt` (не закрыто лишнее), `sitemap.xml` (актуальный, в GSC),
  `noindex`/`nofollow` там, где надо; проверь покрытие в GSC (Pages).
- **Каноникализация:** `rel=canonical` на дублях, единый хост и протокол, слеши,
  параметры, пагинация.
- **Мультиязычность:** `hreflang` (включая `x-default`), согласованность с canonical.
- **Структурированные данные:** JSON-LD (рекомендуемый формат) — Organization,
  BreadcrumbList, Product, Article, FAQ и т.п.; валидируй Rich Results Test.
- **Скорость/CWV:** оптимизация LCP-элемента, разбивка длинных задач под INP,
  зарезервированные размеры под CLS.
- **Архитектура:** логичная вложенность URL, ЧПУ, хлебные крошки, внутренняя
  перелинковка на приоритетные страницы, разумная глубина клика.
- **Коды ответов:** 200 на нужном, 301 на переездах, 404/410 на удалённом, никаких
  цепочек редиректов.

## Семантика под Google

1. Собрать идеи: Keyword Planner, GSC (реальные запросы, где уже есть показы),
   автоподсказки, People Also Ask, «Похожие запросы».
2. Разметить интент (инфо / коммерция / навигация / транзакция).
3. Сгруппировать по интенту и посадочным (для рунета/RU-фраз — см. `morphology.md`:
   лемматизация и кластеризация ядра).
4. Приоритизация: спрос × реализуемость (текущие позиции из GSC, конкуренция).
5. Заложить SERP-фичи: featured snippet, People Also Ask, картинки/видео, локальный пак.

### GEO / AEO — видимость в AI-выдаче

Google AI Overviews и LLM-ответы всё чаще перехватывают клики. Что помогает
цитируемости: чёткие прямые ответы в начале блока, фактурность и источники,
структура (списки, таблицы, FAQ-разметка), сущностная ясность (кто/что/где),
свежесть. Проверяй, по каким запросам показывается AI Overview и что он цитирует.

## On-page

- **Title** — уникальный, ключ ближе к началу, ~50–60 знаков (Google может переписать).
- **Meta description** — не фактор ранжирования, но влияет на CTR; ~150–160 знаков.
- **H1** один, далее логичная иерархия H2/H3 под подтемы и PAA.
- **Контент** — закрывает интент полнее конкурентов из ТОПа; сущности и подтемы,
  а не плотность ключей.
- **Изображения** — `alt`, сжатие, современные форматы, `width`/`height` под CLS.
- **Внутренние ссылки** — осмысленные анкоры на связанные страницы.

## Метрики и мониторинг

- **Позиции/клики/показы/CTR** — GSC (Performance); ищи страницы на позициях 5–15
  (быстрый рост) и запросы с высоким показом и низким CTR (доработать сниппет).
- **Индексация** — GSC Pages: что исключено и почему.
- **CWV** — CrUX/PageSpeed по ключевым шаблонам страниц.
- **Каннибализация** — несколько URL по одному запросу; свести к одной посадочной.
- **Поведение и конверсии** — GA4.

## Особенности рунета для Google

В России доля Google значительна, но не доминирует. Если проект под рунет —
оптимизируй под **оба** движка: техбаза общая, но семантику, регион и поведенческие
факторы отрабатывай ещё и под Яндекс (см. `yandex.md`). Не переноси слепо
google-практики на Яндекс — там иначе работают поведенческие и региональность.
